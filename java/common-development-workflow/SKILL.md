# 通用开发工作流程规范

## 工作流程概述

**核心原则**：所有代码修改任务必须严格遵循以下6步工作流程，确保代码质量和流程规范性。

## 标准工作流程

### 步骤 1：生成分析文档

在执行任何代码修改之前，**必须先生成分析文档**。

**要求**：
- 分析当前代码结构和相关文件
- 明确需要修改的内容和范围
- 识别可能的影响和依赖关系
- 列出需要修改的文件清单
- 说明修改的原因和目标

**输出格式**：
```
## 分析文档

### 修改目标
[说明需要实现的功能或修复的问题]

### 涉及文件
- [文件路径 1]：说明修改内容
- [文件路径 2]：说明修改内容

### 影响分析
[分析对其他模块或功能的影响]

### 依赖关系
[列出相关的依赖和前置条件]
```

### 步骤 2：确认后生成实施文档

**必须等待用户确认分析文档后**，才能生成实施文档。

**要求**：
- 基于确认后的分析文档
- 制定详细的实施计划
- 列出具体的代码修改步骤
- 说明每个步骤的修改内容
- 定义代码优化的标准

**输出格式**：
```
## 实施文档

### 实施步骤
1. [步骤 1]：具体操作和修改内容
2. [步骤 2]：具体操作和修改内容

### 代码修改清单
- [文件路径]：[具体修改点 1]
- [文件路径]：[具体修改点 2]

### 优化计划
[列出需要优化的方面：清理无引用代码、重构等]
```

### 步骤 3：修改代码

按照实施文档执行代码修改。

**要求**：
- 严格按照实施文档执行
- 保持代码风格一致性
- 遵循项目编码规范
- 添加必要的注释
- 确保代码逻辑正确

**禁止事项**：
- 不要跳过分析文档和实施文档直接修改代码
- 不要偏离实施文档的计划
- 不要同时修改多个不相关的功能

### 步骤 4：优化本次修改的代码

代码修改完成后，**必须进行代码优化和清理**。

**优化内容**：
- ✅ **清理无引用的类**：检查并删除未被使用的类
- ✅ **清理无引用的方法**：检查并删除未被调用的方法
- ✅ **清理无引用的变量**：检查并删除未被使用的变量、导入等
- ✅ **代码重构**：优化代码结构，提高可读性
- ✅ **注释完善**：确保关键代码有必要的注释

**检查清单**：
- [ ] 是否删除所有无引用的类
- [ ] 是否删除所有无引用的方法
- [ ] 是否删除所有无引用的变量和导入
- [ ] 代码是否符合项目规范
- [ ] 是否有必要的注释

### 步骤 5：编译验证

代码优化完成后，**必须进行编译验证**。

**验证内容**：
- ✅ 检查编译错误
- ✅ 检查编译警告
- ✅ 验证代码语法正确性
- ✅ 检查依赖关系

**要求**：
- 确保代码能够成功编译
- 修复所有编译错误
- 尽量消除编译警告
- 验证依赖是否正确

### 步骤 6：Git 操作控制

**重要规则**：**除非用户明确要求，否则不得进行任何 Git 相关操作**。

**禁止的操作**：
- ❌ 不能自动提交代码
- ❌ 不能自动创建分支
- ❌ 不能自动推送代码
- ❌ 不能自动合并分支
- ❌ 不能自动打标签

**允许的操作**：
- ✅ 用户明确要求 Git 操作时
- ✅ 用户明确要求提交代码时
- ✅ 用户明确要求推送代码时

## 工作流程图

```
开始
  ↓
步骤 1：生成分析文档
  ↓
等待用户确认
  ↓
步骤 2：生成实施文档
  ↓
等待用户确认
  ↓
步骤 3：修改代码
  ↓
步骤 4：优化代码（清理无引用代码）
  ↓
步骤 5：编译验证
  ↓
步骤 6：Git 操作控制（默认不执行）
  ↓
结束
```

## 最佳实践

### 1. 严格遵守流程顺序

**错误示例**：
- ❌ 直接修改代码，跳过分析文档
- ❌ 修改代码后才发现需要补充分析

**正确示例**：
- ✅ 先完成分析文档，等待确认
- ✅ 再完成实施文档，等待确认
- ✅ 最后执行代码修改

### 2. 完整的代码清理

**错误示例**：
- ❌ 只修改代码，不清理无引用代码
- ❌ 只清理类，不清理方法和变量

**正确示例**：
- ✅ 清理所有无引用的类、方法、变量
- ✅ 清理无用的导入
- ✅ 确保代码整洁

### 3. 编译验证必须执行

**错误示例**：
- ❌ 修改代码后不验证编译
- ❌ 忽略编译警告

**正确示例**：
- ✅ 每次修改后都进行编译验证
- ✅ 修复所有编译错误
- ✅ 尽量消除编译警告

### 4. Git 操作谨慎控制

**错误示例**：
- ❌ 自动提交代码
- ❌ 未询问用户就推送代码

**正确示例**：
- ✅ 默认不执行 Git 操作
- ✅ 用户明确要求时才执行
- ✅ 执行前询问确认

## 注意事项

1. **流程不可跳过**：每个步骤都必须执行，不能省略
2. **确认环节重要**：步骤 1 和步骤 2 必须等待用户确认
3. **代码清理必要**：步骤 4 必须清理所有无引用代码
4. **编译验证必需**：步骤 5 必须执行编译验证
5. **Git 操作默认禁止**：步骤 6 默认不执行任何 Git 操作，除非用户明确要求
